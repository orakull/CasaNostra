# Casa Nostra - Roadmap & Requirements 🎵

## 1. Ревью функциональных требований
Функциональные требования и выбранный технологический стек (KMP, Compose, Ktor, Supabase, SQLDelight) составлены отлично и идеально подходят для реализации задуманного продукта. 

**Ключевые технические вызовы и рекомендации:**
1. **Аудио-форматы и точность синхронизации:** MP3 кодек по своей природе добавляет небольшую тишину в начало и конец файла (encoder padding). Для обеспечения строгих требований задержки (5-10мс) между дорожками лучше использовать **WAV** (минус — большой размер) или форматы, лучше поддерживающие gapless playback, например **M4A/AAC** или **Ogg/Opus**.
2. **Синхронизация в Web (Wasm):** Воспроизведение через стандартный HTML-тег `<audio>` не даст идеальной синхронности. Потребуется использование **Web Audio API**: декодирование треков в память (`AudioBuffer`) и их одновременный старт через `AudioBufferSourceNode`. Для больших файлов это потребует RAM-памяти на клиенте.
3. **Производительность UI (Compose Multiplatform):** При движении ползунков громкости (60 FPS) крайне важно, чтобы состояние ползунков было изолировано. Избегайте рекомпозиции всего плеера или списка треков; обновляйте только конкретный ползунок, передавая значения напрямую в аудиодвижок (через Side Effects / StateFlow без лишних UI подписчиков).

## 2. Этапы реализации (Roadmap MVP)

### Этап 1: Ядро (KMP-проект и базовый аудио-плеер)
**Цель:** Добиться идеальной синхронизации 2-3 локальных дорожек на всех платформах.
*   Настройка архитектуры KMP и Compose Multiplatform.
*   Выделение общего интерфейса `MultitrackPlayer` в Shared-модуле.
*   **Android:** Реализация плеера на базе `Media3` (ExoPlayer).
*   **iOS:** Реализация плеера на базе `AVFoundation` (`AVAudioEngine`).
*   **Web (Wasm):** Реализация через JS Interop и `Web Audio API`.
*   UI микшера: Базовые элементы управления (Play/Pause, Ползунки громкости, Mute, Solo).

### Этап 2: Бэкенд и Хранилище (Supabase)
**Цель:** Интеграция облака для управления пользователями и файлами.
*   Интеграция Supabase Auth (Email + Google).
*   Создание базовых таблиц (Projects, Tracks) в PostgreSQL.
*   Настройка политик доступа RLS (Row Level Security).
*   Загрузка и потоковое чтение (download) партий из Supabase Storage (S3-совместимое) по Signed URLs.

### Этап 3: Локальное хранение и Offline-режим
**Цель:** Бесшовный опыт без интернета.
*   Интеграция `SQLDelight` для создания локальных таблиц кэша.
*   Сущность `UserTrackSettings` (настройки микса: громкость, mute, solo) в локальной БД.
*   Кэширование скачанных из облака аудиофайлов во внутреннюю память устройства.
*   Реализация механизма синхронизации: локальные изменения настроек отправляются на сервер при появлении сети.

### Этап 4: Система проектов и Шеринг
**Цель:** Совместный доступ и управление проектами.
*   UI создания проекта и загрузки дорожек.
*   Система ролевого доступа: Владелец, Редактор, Слушатель (Только чтение).
*   Генерация уникальной ссылки-инвайта на проект (Universal Links / Deep Links).
*   Анонимный доступ по ссылке (Guest Auth в Supabase).

### Этап 5: UX-Полировка и Тестирование
**Цель:** Доведение до плавного 60-FPS опыта и тестирование "в полях".
*   Оптимизация UI: Анимации, обработка состояний загрузки (Loading, Error).
*   Тестирование на реальном хоре: Сбор фидбека по удобству UI и качеству рассинхрона.
*   Подготовка к релизным сборкам (TestFlight, Google Play Console, Web Hosting / GitHub Pages).
